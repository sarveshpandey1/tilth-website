GA4 conversion tracking: the setup checklist before you scale ads

If GA4 is reporting the wrong conversions, every decision downstream — which campaign to scale, which to cut — is built on a lie. Here's the checklist to get it right before you spend more.

Anuja Founder, Tilth · 10+ years in performance marketing

Most GA4 properties are collecting data. Far fewer are collecting data anyone should make a budget decision on. The gap is rarely the install — it is what got marked as important, what fires twice, and what was never verified before paid media started optimising against it. Work through these in order.

1. Mark the right events as key events

In GA4 the events that matter to the business are called key events — an event that measures an action particularly important to your success. You mark them on the Key events page in Admin. Everything else stays an ordinary event, which is fine: ordinary events are still collected and still reportable.

Two practical cautions. First, be sparing. If twelve things are key events, nothing is, and every report becomes a negotiation about which number to believe. Second, renaming an event that is already marked as a key event removes its key-event status — changing only its parameters does not. That single behaviour explains a lot of conversions that silently vanished after a tagging tidy-up.

2. Send the revenue event with value and currency

A purchase that reports no value cannot support any decision about return. Send the ecommerce purchase event with value, currency and a stable transaction_id. The transaction ID is what lets you deduplicate later and reconcile against your backend, and it is the field most often left out.

For lead generation the equivalent discipline is deciding what a lead is worth before you start optimising toward it. A form fill with no value assigned is just a count, and counts cannot be compared across channels with different qualification rates.

3. Find the duplicate events before they find you

Duplicates usually come from one of three places: the same tag deployed twice, once directly and once through a tag manager; a thank-you page that can be reloaded or revisited; or an event fired both on a button click and on the confirmation that follows. The symptom is a conversion count that exceeds your order count, which nobody notices while it flatters performance.

Check against the backend, not against another analytics tool. If GA4 says 180 purchases and your order system says 143, the question is which 37 are not real.

4. Prefer the confirmation event to the thank-you page

Counting a thank-you page view as the conversion is convenient and fragile: the page can be bookmarked, refreshed, shared, or reached without ordering. An event fired at the point the order is actually created is harder to trigger accidentally. Where you have no choice but to rely on the page, at least carry the transaction ID so repeats can be identified and discarded.

5. Know what enhanced measurement is doing for you

Enhanced measurement collects a set of interactions with no code changes, and the detail matters when you start reporting on them. Page views are collected automatically and that collection cannot be switched off. The scroll event fires the first time 90% vertical depth becomes visible — it is not a general engagement measure. Outbound clicks do not fire for domains you have configured for cross-domain measurement, which is correct behaviour but surprises people. Site search looks for query parameters, defaulting to q, s, search, query and keyword, so a site using something else records nothing until it is added. Form interaction events are collected, but their parameters are only usable in reports once you create custom dimensions for them.

Google also states plainly that it is your responsibility to ensure no personally identifiable information is collected. Worth re-reading if your URLs carry email addresses or order details in query strings.

If GA4 and your order system disagree, GA4 is not a second opinion. It is a hypothesis that failed a test.

6. Fix cross-domain and referral noise before you trust sources

If your journey crosses domains — a separate checkout, a booking engine, a payment page — configure cross-domain measurement, and note the hard requirement: every page must use the same G- measurement ID from the same web data stream. Without it a single visitor becomes two users and two sessions, and the channel that introduced them loses the sale. Analytics carries identity across with a _gl parameter, so verify it survives the hop; redirects that strip it, JavaScript-triggered navigation, and scripts calling Event.stopPropagation() are the usual culprits.

Separately, list unwanted referrals for domains that should not be credited as a traffic source — third-party payment processors being the standard case, where customers return from the gateway and the gateway appears to have sold your product. GA4 appends an ignore_referrer flag to matching events, and allows up to 50 such entries per data stream. One caveat worth knowing before you expect it to rewrite history: a session already referred by that domain can still be credited to it under last-non-direct-click attribution.

7. Verify in DebugView before you believe the reports

DebugView shows the events and user properties Analytics is collecting in real time, which is the only honest way to confirm a tag does what you think. Enable debug mode with Tag Assistant for your own session, or set debug_mode: true in your configuration to see it for all users, then open DebugView under Data display in Admin. Note that setting the parameter to false does not switch debug mode off — you remove it.

One consent-related gotcha: where consent mode is in use and a visitor has not consented to Analytics cookies, their events will not appear in debug mode. An empty DebugView is not automatically a broken tag.

8. Understand what consent does to your totals

If you ask for analytics consent — and in many markets you must — a share of visitors will decline, and those sessions are not fully measured. That is the correct outcome, not a bug to engineer around. The implication is that GA4 totals are a floor, your backend is the truth for revenue, and your reported conversion rate will sit below reality by an amount that varies with your consent rate. Decide that before you compare this quarter with a period measured under different rules.

9. Import to Google Ads deliberately

You can create a Google Ads conversion from a GA4 key event. Import one — the revenue event — and be aware that Google Ads conversions do not appear in standard GA4 reports, so the two interfaces are not meant to tie out line for line. Importing several overlapping events is how bidding ends up optimising toward the same customer counted three ways.

What must be true before you scale paid media

One revenue event, marked as a key event, carrying value, currency and a transaction ID. Count reconciled against the backend within a tolerance you have written down. Cross-domain configured and verified if the journey crosses domains. Payment processors excluded from referrals. The event confirmed firing once in DebugView. One conversion imported to Google Ads. If any of those is missing, extra budget buys noise at scale.
