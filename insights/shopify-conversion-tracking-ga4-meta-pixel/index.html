How to set up conversion tracking on Shopify (GA4 + Meta Pixel)

Most Shopify stores have "tracking installed" and still can't trust the numbers. Here's how GA4, the Meta pixel and the Conversions API are actually supposed to be set up on Shopify today — including the theme-code method that stopped working, and how to verify each step.

Anuja Founder, Tilth · 10+ years in performance marketing

Almost every Shopify store we audit has GA4 and the Meta pixel "installed." Fewer have them installed the way Shopify currently supports. Apps report a green tick, events appear somewhere in a dashboard, and everyone assumes the numbers are right — until platform revenue and Shopify's own reports stop agreeing and nobody can say which one is wrong. This guide covers Shopify conversion tracking as it works today: GA4, the Meta pixel, the Conversions API, and the older method that no longer reaches checkout at all.

Four ways tracking gets onto a Shopify store

Most confusion here comes from mixing these up, so separate them before touching anything:

  • Native sales channels — the Google & YouTube and Facebook & Instagram channels in your admin. Configuration, not code, and the right default for a standard store.
  • App pixels and custom pixels — Shopify's pixel system, managed in the Customer events section. App pixels arrive with an app; custom pixels are added manually by a developer.
  • Google Tag Manager — loaded through a custom pixel, subscribing to Shopify's customer events and pushing them into the data layer. Still runs inside the pixel sandbox.
  • Server-side — Meta's Conversions API, which on Shopify comes with the data-sharing level you choose rather than a separate build.

Shopify runs app and custom pixels in a sandbox: an isolated environment that can't render UI and can't scrape the DOM for things like email addresses or scroll depth. Worth knowing before someone promises you an event the sandbox can't produce.

The theme-code method that stopped working

If someone set your tracking up by pasting snippets into theme.liquid or into checkout customisations, there's a good chance it no longer reaches the part of the funnel that matters. Shopify has deprecated checkout.liquid; additional scripts and script tags on the Thank you and Order status pages were sunset for Shopify Plus stores on 28 August 2025, and script tags on those pages are being sunset for non-Plus stores on 26 August 2026. The supported replacement is apps, checkout UI extensions and web pixels.

The current architecture is better than what it replaced. Shopify's documentation states that pixels automatically load on the storefront, checkout, Thank you page and Order status page — exactly the coverage hand-pasted theme code could never reliably achieve. The fix for a legacy setup isn't more script; it's moving to the channels and the pixel manager.

A pixel that fires on your homepage but not at checkout isn't broken. It's telling you nothing about whether ads convert, confidently.

What you need before you start

  • Admin access to your store (Sales channels, and the Customer events section)
  • A GA4 property and its tag ID
  • A Meta Business account with a pixel created
  • One real test order you're willing to place and refund

Setting up GA4 on Shopify

1. Connect through the Google & YouTube channel

Install the Google & YouTube sales channel and connect your GA4 property through it rather than pasting a gtag snippet into theme code. You don't need a Google Merchant Center account to complete GA4 setup — Shopify says so explicitly, which saves a step people often think is mandatory.

2. Don't go looking for an "enhanced ecommerce" switch

This is where older guides send people in circles. Shopify's current documentation doesn't use that phrase and doesn't describe a toggle: once your GA4 tags are set up, certain ecommerce events are tracked automatically — product views, add-to-cart, purchase. What will silently block everything is private mode: Shopify notes that Google Analytics can't track events until password protection on your online store is deactivated.

3. Verify in DebugView, not Realtime

Place a test order and watch GA4's DebugView. Confirm exactly one purchase event, with the correct value, currency and transaction ID. This is the step almost everyone skips, and it's where most GA4 tracking problems actually surface.

Setting up the Meta pixel and Conversions API

1. Install through the Facebook & Instagram channel

Add the Facebook & Instagram sales channel (the app is listed as Facebook and Instagram by Meta) and connect your pixel there. If a pixel was previously added to theme code, Shopify is explicit that you must remove it first: leaving both means more than one pixel on the store, "which can result in duplicate or incorrect data in your reports."

2. Choose a data-sharing level — this is where CAPI lives

There's no separate "enable Conversions API" button. In the channel's data-sharing settings you choose Standard, Enhanced or Maximum. Shopify states that Standard collects browsing behaviour via the pixel; Enhanced uses the Conversions API as well as the pixel; Maximum uses the API, the pixel, and Meta's latest advertising technology. Enhanced and Maximum also send additional customer information such as name, location and email address — which is why the level you pick is a privacy decision, not just a performance setting.

3. Understand what the server-side send does and doesn't do

Meta describes the Conversions API as a connection from your server to the systems that optimise targeting and measure outcomes, and recommends implementing it alongside the pixel. That's the accurate framing. It is not a way around consent and it doesn't change what you're allowed to collect — Shopify's own pixel documentation is blunt that merchants remain responsible for consent requirements. In markets configured to require consent, typically the EEA and UK, Shopify states that web pixels run only when visitors have given the required permissions, and that new pixels require Marketing and Analytics permissions by default.

Deduplication: the part that's genuinely specific

Running the pixel and the Conversions API together means the same purchase can be reported twice, so Meta's deduplication rules matter. Meta documents two methods. The recommended one matches on event ID and name: the pixel's eventID must match the API's event_id, and the pixel's event must match event_name. The alternative uses event_name with fbp and/or external_id consistently across browser and server — and Meta notes that generally only works when the browser event arrives first. There's a window too: Meta discards subsequent duplicates received within 48 hours of the first event with a given ID, and where events don't differ meaningfully it prefers whichever arrived first. For a Shopify store the practical test is simple — one Purchase event showing both Browser and Server as sources is healthy; two separate Purchase events are not.

How to verify everything

  1. Place one real test order end to end — a near-zero discount code is fine if you'd rather not refund a full order.
  2. Confirm a single purchase event in GA4 DebugView with the correct value, currency and transaction ID — not zero, not twice.
  3. Confirm a single Purchase event in Meta Events Manager with both Browser and Server sources present.
  4. Compare GA4 revenue against Shopify's own reports for that order. They should be close; don't expect them to match exactly, because the two count differently and GA4 depends on a browser executing a tag.
  5. Reload the order confirmation page and confirm the purchase event does not fire again.

The failures we see most often

  • Two pixels firing — a leftover theme snippet plus the native channel, doubling events. Shopify warns about this directly.
  • Purchase firing on reload — the confirmation page re-fires on every load, inflating both platforms.
  • Currency mismatch — GA4 property currency set differently from the store's checkout currency, skewing reported revenue quietly.
  • Legacy checkout scripts — tracking that was added through methods Shopify has since sunset, now missing the checkout stage entirely.
  • Trusting the dashboard tick — "connected" confirms a tag loaded, not that the right event fired once with the right value.

None of this is exotic, but it's the layer most D2C and ecommerce brands scale spend on top of without ever verifying. Once tracking is confirmed end to end, run the same sanity check on the campaigns themselves with a quick ad spend self-audit — and if the store's measurement needs rebuilding rather than patching, that's tracking and measurement architecture work, not an app install.
